Mahmoodi

I build AI-enhanced decision systems — software that tells an organisation what to do next, and what it costs to do something else.

Most analytics stops at describing what happened. My work goes one step further and produces the decision itself: how many vehicles to run, when to schedule maintenance, which material to specify, how many service centres a region needs. Optimisation and simulation underneath, a working application on top, and a business case that says plainly whether it pays.

How every modelling project runs

Each project on the timeline is tagged with the stages it covered, in these colours.

  1. EngageQualitative Listen to the people who own the problem, then formulate it properly before modelling anything. Stakeholder interviews · process mapping · problem formulation · AHP / ANP judgement
  2. DescribeDescriptive Data from the system — historical records, or a live connection that re-reads the plant’s data as it updates. SQL · pandas · live data connections · SCADA / historian · distribution fitting
  3. DiagnoseDiagnostic Why the system behaves the way it does — the root cause, not the symptom. Bottleneck analysis · segmentation · anomaly detection · DEA · sensitivity
  4. PredictPredictive Build the model, then verify and validate it: statistical tests against real data, face validation through animation. Discrete-event simulation · digital twins · XGBoost · survival models · financial models
  5. PrescribePrescriptive Use the validated model to decide, with the trade-offs stated rather than hidden. NSGA-II · OptQuest · MCDM (TOPSIS, AHP) · multi-agent AI
  6. DeliverSoftware A working application the client runs without me in the room. Python · Streamlit · Plotly · pytest · Azure · Azure OpenAI
